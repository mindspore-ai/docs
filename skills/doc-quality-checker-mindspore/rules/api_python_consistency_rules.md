# Python API中文与英文一致性检查规则

## 一致性检查概述

中文API文档必须与对应的英文源码保持一致，包括模块结构、接口数量、参数定义、返回值说明等。

## 模块结构一致性

### 检查项

| 编号 | 检查项 | 要求 | 验证方法 |
|-----|-------|------|---------|
| I-CN-M-01 | 模块层级 | 中文文档与英文源码的模块结构一致 | 对比目录结构 |
| I-CN-M-02 | 文件命名 | 中文文档文件名与英文源码的模块对应 | 路径匹配检查 |
| I-CN-M-03 | 接口数量 | 每个模块下的接口数量一致 | 统计对比 |

## 接口定义一致性

### 函数/方法签名一致性

| 编号 | 检查项 | 中文文档 | 英文注释 | 一致性要求 |
|-----|-------|---------|---------|-----------|
| I-CN-D-01 | 函数名 | `.. py:function:: name(params)` | `def name(params):` | 完全一致 |
| I-CN-D-02 | 类名 | `.. py:class:: ClassName` | `class ClassName:` | 完全一致 |
| I-CN-D-03 | 参数名 | `**param_name**` | `param_name` | 完全一致 |
| I-CN-D-04 | 参数类型 | `(Type)` | `(Type)` | 完全一致 |
| I-CN-D-05 | 参数顺序 | 按定义顺序 | 按定义顺序 | 完全一致 |
| I-CN-D-06 | 默认值 | `默认值： ``xxx`` 。` | `Default: ``xxx``.` | 完全一致 |

### 验证规则

```text
中文RST参数: - **input_data** (Tensor) – 输入数据。
英文注释参数: input_data (Tensor): Input data of the tensor.

→ 必须一致：参数名、类型、说明
```

## 描述内容一致性

以下"英文注释"泛指英文源文件中的对应内容，Python docstring 和 YAML 的字段名不同但映射关系一致：

| 英文源类型 | 对应字段 |
|-----------|---------|
| Python docstring | Summary, Args, Returns, Raises |
| YAML doc | `description`, `parameters`, `returns`, `raises` |

### Summary/描述一致性

| 编号 | 中文文档 | 英文注释 | 检查要点 |
|-----|---------|---------|---------|
| I-CN-S-01 | 类描述 | Summary | 功能描述一致 |
| I-CN-S-02 | 方法描述 | Summary | 功能描述一致 |
| I-CN-S-03 | 函数描述 | Summary | 功能描述一致 |

**检查规则：**

- 主要功能描述必须一致
- 详细程度可以不同（中文可以更详细）
- 禁止出现矛盾描述

### Args/参数一致性

| 编号 | 中文文档 | 英文注释 | 检查要点 |
|-------|---------|---------|---------|
| I-CN-A-01 | 参数数量 | Args数量 | 必须相等 |
| I-CN-A-02 | 参数名 | 参数名 | 必须一致 |
| I-CN-A-03 | 参数类型 | 类型 | 必须一致 |
| I-CN-A-04 | 参数说明 | Description | 语义一致 |
| I-CN-A-05 | 可选标注 | optional | 必须一致 |
| I-CN-A-06 | 默认值 | Default | 必须一致 |

### Returns/返回一致性

| 编号 | 中文文档 | 英文注释 | 检查要点 |
|-------|---------|---------|---------|
| I-CN-T-01 | 返回值数量 | Returns | 必须一致 |
| I-CN-T-02 | 返回值类型 | Type | 必须一致 |
| I-CN-T-03 | 返回值说明 | Description | 语义一致 |
| I-CN-T-04 | shape变化 | shape说明 | 必须一致 |

### Raises/异常一致性

| 编号 | 中文文档 | 英文注释 | 检查要点 |
|-------|---------|---------|---------|
| I-CN-E-01 | 异常类型 | Raises | 必须一致 |
| I-CN-E-02 | 异常数量 | 异常数量 | 可以不同（中文可以更全） |
| I-CN-E-03 | 异常说明 | Description | 语义一致 |

**检查规则：**

```text
中文RST: 异常：
    - **ValueError** – 参数值不合法。
    - **TypeError** – 参数类型错误。
英文注释: Raises:
    ValueError: If input is invalid.

→ 异常类型必须一致，说明可以简化
```

## PR中的中英文修改配对检查

### 检查场景

当输入为AtomGit PR链接时，需要检查PR中的文档修改是否配对：

| 编号 | 修改类型 | 要求配对 |
|-----|---------|---------|
| I-PR-M-01 | 中文文档新增 | PR中必须有对应的英文注释/yaml新增 |
| I-PR-M-02 | 中文文档修改 | PR中必须有对应的英文注释/yaml修改 |
| I-PR-M-03 | 英文注释新增 | PR中必须有对应的中文文档新增 |
| I-PR-M-04 | 英文注释修改 | PR中必须有对应的中文文档修改 |
| I-PR-M-05 | YAML新增 | PR中必须有对应的中文文档新增 |
| I-PR-M-06 | YAML修改 | PR中必须有对应的中文文档修改 |

### 配对检查规则

#### 与一致性检查的关系

PR配对检查（增量视角）和一致性检查（存量视角）在实践中可能同时命中同一个问题：

| 检查类型 | 视角 | 触发条件 | 仅在PR输入时执行 |
|---------|------|---------|----------------|
| 一致性检查（I-CN-\*） | 当前文件状态 | 中英文内容不匹配 | 否 |
| PR配对检查（I-PR-\*） | 本次PR变更集 | PR只改了单侧 | 是 |

**当PR只修改中文（或只修改英文）时，两个检查会得到同一结论**：

- PR配对：本次PR没改另一侧（增量缺漏）
- 一致性：改完后两侧对不上（存量不一致）

**合并规则：** 检查报告中，对同一组中英文文件的同一个不一致问题，**只记录一次**。优先归入一致性检查（I-CN-\*），PR配对检查（I-PR-\*）仅报告无法被一致性覆盖的增量问题（如新增接口无对应、删除接口无对应）。消除重复项后更新总计数量。

#### 1. 中文文档修改必须有英文对应

| 编号 | 中文修改内容 | 要求英文有对应修改 |
|-----|-------------|-------------------|
| I-PR-C-01 | 新增接口文档 | 英文代码中必须有对应的接口注释 |
| I-PR-C-02 | 修改接口描述 | 英文注释必须有对应修改 |
| I-PR-C-03 | 新增/修改参数 | 英文注释必须有对应修改 |
| I-PR-C-04 | 新增/修改返回值 | 英文注释必须有对应修改 |
| I-PR-C-05 | 新增/修改异常 | 英文注释必须有对应修改 |
| I-PR-C-06 | 新增/修改示例 | 英文注释或yaml必须有对应修改 |

#### 2. 英文注释/YAML修改必须有中文对应

| 编号 | 英文修改内容 | 要求中文有对应修改 |
|-----|-------------|-------------------|
| I-PR-E-01 | 新增接口注释 | 中文文档必须有对应文档 |
| I-PR-E-02 | 修改接口描述 | 中文文档必须有对应修改 |
| I-PR-E-03 | 新增/修改参数 | 中文文档必须有对应修改 |
| I-PR-E-04 | 新增/修改返回值 | 中文文档必须有对应修改 |
| I-PR-E-05 | 新增/修改示例 | 中文文档必须有对应修改 |
| I-PR-E-06 | yaml修改 | 中文文档必须有对应修改 |

## 别名场景一致性检查要点

当通过 import 链发现别名映射时，额外检查以下内容：

| 编号 | 检查项 | 说明 | 严重程度 |
|-----|-------|------|---------|
| I-CN-AL-01 | 类名/函数名差异 | 中文RST用别名（如 `Hardshrink`），英文源码用原名（如 `HShrink`），需确认功能完全一致 | 一般 |
| I-CN-AL-02 | 模块重导出内容一致性 | 别名模块的 `__init__.py` 重导出时，需确认参数签名未被包装/修改 | 严重 |
| I-CN-AL-03 | YAML 与 RST 名称匹配 | 中文RST使用新名称（如 `Hardshrink`），但 YAML doc 文件可能以原名命名（如 `hshrink_doc.yaml`），需检查两者是否对应同一接口 | 一般 |
| I-CN-AL-04 | 废弃/重命名标注 | 如果别名因重命名引入，英文源码应有 `warning` 说明（如 `After version 2.9.0, this interface will be renamed to Hardshrink`） | 建议 |

## 英文RST目录文件一致性

### 英文RST目录文件结构

英文API文档采用目录文件组织API索引，典型结构：

```text
api_python_en/
├── mindspore.rst          # 主模块索引
├── mindspore.nn.rst      # nn子模块索引
├── mindspore.ops.rst     # ops子模块索引
├── mindspore/
│   ├── mindspore.Tensor.rst
│   └── ...
└── nn/
    ├── mindspore.nn.Cell.rst
    └── ...
```

**目录文件格式示例：**

```rst
mindspore.nn
==========

Neural Network Cell
-------------------

.. msplatformautosummary::
    :toctree: nn
    :nosignatures:
    :template: classtemplate.rst

    mindspore.nn.Cell
    mindspore.nn.GraphCell
    mindspore.nn.LossBase
    mindspore.nn.Optimizer
```

## 常见错误汇总

### 模块结构不一致

1. 中文文档缺少英文源码中存在的接口
2. 中文文档多了英文源码中不存在的接口
3. 模块层级不对应

### 参数定义不一致

1. 参数名不一致：`**input_data**` vs `input_data`
2. 参数类型不一致：`(Tensor)` vs `(int)`
3. 参数顺序不一致
4. 默认值写法不一致：`默认值： ``1`` 。` vs `Default: ``1``.`
5. 可选标注不一致：`可选` vs `optional`
6. 二级参数不一致

### API别名与重命名问题

1. 别名映射未识别（中文RST与英文源码名称不同但功能相同）
2. 别名功能不一致（描述/参数/返回值不匹配）
3. 别名导入链未追溯（`mint.nn` 等模块通过 `__init__.py` 重导出，一致性检查需追踪到真实定义文件，而非仅检查 `method_doc` 中的简短 YAML）
4. YAML doc 以原名命名（如 `hshrink_doc.yaml`），中文 RST 使用别名（如 `Hardshrink`），导致 YAML 搜索漏匹配
5. 重命名标注缺失：一面标注了重命名 warning，另一面（原名或别名 RST）未标注

### 返回值/异常不一致

1. 返回值类型不一致：`返回：Tensor` vs `Returns: int`
2. 返回值说明语义不一致
3. 异常类型不一致：`ValueError` vs `TypeError`
4. 异常数量差异（中文更全但英文缺失）

### 描述内容不一致

1. 描述语义差异（说明意思不完全一致）
2. 详细程度差异（中文可以更详细）
3. 中文补充了英文未说明的内容

### PR配对问题

1. 中文新增无英文对应
2. 英文新增无中文对应
3. 中文修改无英文同步
4. 英文修改无中文同步

### RST目录不一致

1. 接口数量不一致（中文10个 vs 英文8个）
2. 接口名称不一致（`mindspore.nn.ReLU` vs `nn.ReLU`）
3. 分组方式不同（字母排序 vs 功能分组）
4. 目录结构缺失
