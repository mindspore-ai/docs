# 通用性检查规则

## 一、低错性

核心目标：消除拼写、语法、格式、链接等低级错误。

### 1.1 文本层面

| 编号 | 要求 |
|------|------|
| G-L-01 | 无拼写错误（含中英文混排） |
| G-L-02 | 中文无错别字、语病，英文无语法错误 |
| G-L-03 | 术语全文一致，同一概念不使用多个名称 |
| G-L-04 | 标点符号使用正确（中英文标点不混用） |

### 1.2 链接与引用层面

| 编号 | 要求 |
|------|------|
| G-L-05 | 无死链（内部链接、外部链接均可达），MindSpore官网stable链接的文档不检查链接版本号问题 |
| G-L-06 | 图片路径正确且图片存在，无多余图片（如果英文文档引用了中文路径下的图片，但是该图片的内容都是英文，那么该图片也可以被接受；ipynb文件引用的图片需是完整链接，其余文件引用的图片路径需是相对路径） |

### 1.3 格式层面

| 编号 | 要求 |
|------|------|
| G-L-07 | 公式写法错误，渲染结果异常 |
| G-L-08 | 空格、空行用法准确，其中中英文之间可以不需要空格 |
| G-L-09 | Markdown/reStructuredText/Jupyter Notebook等格式文件语法正确 |
| G-L-10 | Jupyter Notebook中cell的metadata需要完全为空，execution_count需从1开始按顺序标号，nbformat为4，nbformat_minor为4 |
| G-L-11 | 表格格式完整，无缺失列多余列 |
| G-L-12 | 列表格式统一（同层级用相同标记） |
| G-L-13 | 无序或有序列表的前后需要有空行 |

## 二、正确性

核心目标：技术内容准确、代码可运行、逻辑自洽。

### 2.1 逻辑正确性

| 编号 | 要求 |
|------|------|
| G-C-01 | 前后文逻辑自洽，无矛盾 |
| G-C-02 | 因果关系正确 |
| G-C-03 | 数值、公式、单位正确 |
| G-C-04 | 架构图/原理图/流程图/时序图等与文字描述一致 |
| G-C-05 | 错误码/返回值与代码实现一致 |

### 2.2 代码正确性

| 编号 | 要求 |
|------|------|
| G-C-06 | 命令、命令参数等正确 |
| G-C-07 | 样例代码可一键运行 |
| G-C-08 | 导入语句完整，无缺失依赖 |
| G-C-09 | 变量先定义后使用，无 NameError |
| G-C-10 | 变量、函数命名语义化，避免无意义简写 |
| G-C-11 | 无冗余代码、测试代码、废弃代码等 |
| G-C-12 | API 调用签名与实际接口一致 |
| G-C-13 | 输出结果与样例展示一致 |
| G-C-14 | 默认参数值不会导致运行时错误 |
| G-C-15 | 遵循Python、C++、Java等编码风格，通过pylint、cpplint等静态工具检查，无严重问题 |
| G-C-16 | 模拟运行样例代码，确保能按预期执行并获得结果 |

## 三、易用性

核心目标：读者能快速理解并应用信息。

### 3.1 可理解性

| 编号 | 要求 |
|------|------|
| G-U-01 | 使用主动语态，避免被动语态 |
| G-U-02 | 消除歧义代词（"它""这个"指代明确） |
| G-U-03 | 避免长句表达，需根据语义适当断句 |

### 3.2 可操作性

| 编号 | 要求 |
|------|------|
| G-U-04 | 操作步骤有明确的起点和终点 |
| G-U-05 | 关键步骤错误或缺失 |
| G-U-06 | 前置条件明确列出（环境、权限、依赖） |
| G-U-07 | 预期结果可验证（提供检查命令或预期输出） |

## 四、安全性

核心目标：不泄露敏感信息、不引入安全风险。

| 编号 | 要求 |
|------|------|
| G-S-01 | 无硬编码密钥、Token、密码 |
| G-S-02 | 无内部 IP、主机名、内部 URL |
| G-S-03 | 无个人身份信息（邮箱、手机号） |
